<h1 align="center">🔤 Character Utils</h1>

<p align="center">
  <strong>Chrome でページの文字コードを上書きし、入力欄の文字を変換する</strong><br/>
  どちらも右クリックメニューから使える。
</p>

Character Utils は plain JavaScript で書いた Manifest V3 の Chrome 拡張機能である。ビルドは不要で、リポジトリのディレクトリがそのまま拡張機能になる。

## Why Character Utils?

- **エンコードメニューの代わり** — Chrome ではページの文字コードを利用者が選べなくなった。Character Utils はその選択肢を右クリックメニューに戻すので、charset の宣言が間違っているページや宣言のないページも、保存して開き直さずに読める
- **ページの種類を保つ** — 上書きするのは `Content-Type` ヘッダーの charset だけなので、テキストファイルはテキストファイルのまま表示される
- **入力と同じように書き換える** — 変換はブラウザーの文字入力の仕組みを通すので、Ctrl+Z で元に戻せ、React などのフレームワークで作られたページにも新しい値が伝わる

## 🚀 Quick Start

**前提**：デスクトップ版の Chrome

1. このリポジトリを clone する

   ```bash
   git clone https://github.com/amaya382/chrome-character-utils.git
   ```

2. `chrome://extensions/` を開く
3. 「デベロッパー モード」をオンにする
4. 「パッケージ化されていない拡張機能を読み込む」を押し、clone したディレクトリを選ぶ

適当なページの何もないところを右クリックし、「Text encoding」>「Japanese (Shift_JIS)」を選ぶ。ページが再読み込みされ、UTF-8 で書かれたページなら文字化けする。「Page default」を選ぶとページ本来の文字コードに戻る。

更新するときは `git pull` を実行し、`chrome://extensions/` で拡張機能のカードにある再読み込みボタンを押す。

## 📖 Usage

### 文字コードの上書き

ページ上のリンク、画像、入力欄以外の場所を右クリックし、「Text encoding」を開く。文字コードを選ぶとタブが再読み込みされ、ページがその文字コードで解釈される。拡張機能はページのレスポンスヘッダー `Content-Type` に charset を設定しており、この指定は HTML の `<meta charset>` より優先される。

上書きはタブごとに持つ。同じ origin (`https://example.com` など) の中でページを移る間は続き、別の origin へ移るかタブを閉じると解除される。ほかのタブや、ページ内のフレームは自身の文字コードのままになる。

メニューでチェックが付いている項目は、アクティブなタブの上書き状態を表す。「Page default」を選ぶと上書きを外して再読み込みする。この項目名には「Page default (Shift_JIS)」のように、上書きしない場合にページが使う文字コードを表示する。上書き中は、上書きを選んだページに限って、上書き直前に記録した文字コードを表示する。上書き中のページは上書き後の文字コードを返すため、タブが別のページへ移ると項目名は「Page default」だけになる。

選べる文字コードは UTF-8、Shift_JIS、EUC-JP、ISO-2022-JP、GBK、gb18030、Big5、EUC-KR、windows-1252、windows-1251、KOI8-R である。

### 文字の変換

入力欄を右クリックし、「Character Utils」の下から変換を選ぶ。項目は「Convert to fullwidth」(全角へ)、「Convert to halfwidth」(半角へ)、「Convert to hiragana」(ひらがなへ)、「Convert to katakana」(カタカナへ)、「Convert to uppercase」(大文字へ)、「Convert to lowercase」(小文字へ) の 6 つである。欄の中で文字列を選択していればその範囲だけを、していなければ欄全体を変換する。`<input>`、`<textarea>`、編集可能領域 (`contenteditable`) で使え、フレーム内の欄でも使える。

| 文字の種類 | 半角 | 全角 |
| --- | --- | --- |
| 英字、数字、記号 | `A1!~` | `Ａ１！～` |
| スペース | ` ` | `　` (U+3000) |
| カタカナと和文の約物 | `ｱｶﾞﾊﾟ｢｣ｰ` | `アガパ「」ー` |

半角カタカナの後ろに `ﾞ` や `ﾟ` が続くと、`ｶﾞ` → `ガ` のように全角 1 文字にまとまり、半角へ変換すると再び 2 文字に分かれる。前の文字と結合できない `ﾞ` と `ﾟ` は `゛` と `゜` になる。ひらがな、漢字、`ヵ` のように対応する文字がないものはそのまま残る。

ひらがなへの変換とカタカナへの変換は、`カタカナ` ↔ `かたかな`、`ヽヾ` ↔ `ゝゞ` のように 2 種類のかなを入れ替える。半角カタカナは先に全角にするので、`ｶﾞﾅ` は `がな` や `ガナ` になる。`ヷ` や `ー` のように対応するひらがながないカタカナはそのまま残る。

大文字と小文字への変換は Unicode の大文字小文字の規則に従うので、`ａ` のような全角の英字や、ギリシャ文字など他の文字体系の文字も変わる。

変換は Ctrl+Z で元に戻せる。

## 🔒 Permissions

- `contextMenus`：右クリックメニューに項目を追加する
- `declarativeNetRequestWithHostAccess`：ページの `Content-Type` ヘッダーを書き換える
- `scripting`：ページの種類を読み取り、入力欄の文字を変換する
- `storage`：ブラウザーの起動中、タブごとの上書き状態を覚えておく
- すべてのサイトへのアクセス：どのページでも文字コードの上書きと変換をできるようにする

## 🔧 Troubleshooting

### 文字コードが変わらない

先頭に byte order mark (BOM) があるページは、BOM が示す文字コードで必ず解釈され、ヘッダーの指定は無視される。また Chrome は `file://` と `chrome://` のページ、Chrome ウェブストアでは拡張機能を動かさない。

### フォームの再送信を確認される

上書きはページを再読み込みする。フォーム送信の結果を表示しているページでは、再送信してよいかを Chrome が確認する。

### 編集可能領域で変換すると書式が消える

`contenteditable` の領域では、変換後の文字列がプレーンテキストとして選択範囲を置き換えるため、範囲内の太字、リンク、行の構造が失われる。残したい部分を避けて範囲を選ぶ。

## 🧪 Development

| File | Role |
| --- | --- |
| `manifest.json` | 拡張機能の manifest |
| `core.js` | 文字の変換とヘッダールールの生成。background、注入スクリプト、テストで共有する |
| `background.js` | 右クリックメニューを作り、ヘッダールールを設定し、タブごとの上書き状態を管理する |
| `inject.js` | フォーカス中の入力欄を変換するためにページへ注入する関数 |
| `icons/` | 拡張機能のアイコン |
| `test/` | `core.js` の単体テスト |

テストは Node.js 18 以降で実行する。

```bash
node --test
```

編集後は `chrome://extensions/` で拡張機能のカードにある再読み込みボタンを押し、確認に使うページも再読み込みする。
